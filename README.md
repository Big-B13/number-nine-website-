# Storefront Beta — test build

A fully static storefront in plain **HTML + CSS + JS** — no frameworks, no build
tools required to serve it, no external requests. It's a beta/testing
environment for a multi-brand fashion store (Dames / Heren / Merken / Sale /
Winkels / Over ons).

> ⚠️ **All copy, product data, brand names, store addresses and imagery are
> placeholders.** Replace the content in `build.py` before showing this build
> to anyone outside the team. Every page is `noindex,nofollow` and carries a
> yellow BETA banner.

## Repo structure

```
.
├── index.html            home — split campaign hero, USP bar, new arrivals, categories
├── collection.html       all products — category/type filters + sorting (?c=dames|heren|sale)
├── product.html          product detail — reads ?id=p01 … p16
├── cart.html             cart page (checkout disabled in beta)
├── brands.html           brand index (18 placeholder brands)
├── stores.html           store locator (6 placeholder stores)
├── about.html            about page
├── event.html            ROUTE NINE pop-up tour (generated by build_tour.py)
├── account.html          login / register (stubbed)
├── 404.html              not-found page (GitHub Pages serves this automatically)
├── css/
│   └── style.css         the whole design system — edit directly
├── js/
│   ├── app.js            cart, search, filters, sorting, PDP logic — edit directly
│   └── data.js           product data — GENERATED by build.py, do not edit by hand
├── build.py              content generator (menu, products, stores, page copy)
├── .nojekyll             tells GitHub Pages to serve files as-is
└── .gitignore
```

## Run locally

```bash
python3 -m http.server 8080
# → http://localhost:8080
```

Opening `index.html` directly from disk also works (everything is relative and
offline), but a local server is closest to how it behaves on GitHub Pages.

## Publish on GitHub Pages

1. Create a new repository on GitHub, e.g. `storefront-beta` (private is fine).
2. Push this folder:

   ```bash
   git init -b main
   git add .
   git commit -m "Beta storefront"
   git remote add origin git@github.com:YOUR-NAME/storefront-beta.git
   git push -u origin main
   ```

3. In the repo: **Settings → Pages → Source: *Deploy from a branch* →
   branch `main`, folder `/(root)`** → Save.
4. After a minute the site is live at
   `https://YOUR-NAME.github.io/storefront-beta/`.

All links are relative, so the site works from a repo root, a subpath, or any
other static host (Netlify, Vercel, Cloudflare Pages — you can drag the folder
straight in).

## Editing

| What                                | Where                                  | Rebuild?               |
| ----------------------------------- | -------------------------------------- | ---------------------- |
| Menu / category tree                | `NAV` list in `build.py`               | `python3 build.py`     |
| Products, prices, sale, categories  | `_items` list in `build.py`            | `python3 build.py`     |
| Brands, stores, page copy           | `BRANDS` / `STORES` / page functions   | `python3 build.py`     |
| Styling                             | `css/style.css`                        | no — just refresh      |
| Cart / search / filter behaviour    | `js/app.js`                            | no — just refresh      |

Using real photography: add files to an `images/` folder and set a product's
`img` / `img2` to e.g. `images/jas-voor.jpg` in the `_items` list in
`build.py`, then rebuild.

## ROUTE NINE — pop-up tour (`event.html`)

The Germany pop-up tour concept lives on its own tab: **Pop-up Tour** in the menu,
in the footer, and as a teaser block on the home page.

```
event.html         the tour page (concept, route, line-up, budget, FAQ, RSVP)
build_tour.py      ALL tour copy in EN/NL/DE -> regenerates event.html + js/tour-i18n.js
js/tour-i18n.js    GENERATED translations, do not edit by hand
js/i18n.js         the EN/NL/DE switcher itself (hand-written)
img/tour/*.jpg     placeholder imagery for the hero, the four cities and the format
```

Editing the tour copy:

```bash
# open build_tour.py, every string is a ("EN", "NL", "DE") tuple
python3 build_tour.py      # rewrites event.html + js/tour-i18n.js
```

### Language switcher (EN / NL / DE)

`js/i18n.js` is loaded on every page and powers the ENG / NL / DE switch that was
already drawn on `about.html`. It works in two ways:

1. **Keyed** — elements with `data-i18n="..."` are looked up in
   `window.__TOUR_I18N__` (generated from `build_tour.py`). That is the whole
   tour page, fully translated.
2. **By source text** — the `CHROME` dictionary at the top of `js/i18n.js` maps the
   Dutch menu, footer, buttons and form labels to English and German, so the
   navigation translates on every page without touching the HTML. Anything not in
   that dictionary (product names, placeholder body copy) simply stays as it is —
   add a line to `CHROME` to cover it.

The choice is stored in `localStorage` under `n9-lang`. The language shown on a
first visit is the `DEFAULT` constant at the top of `js/i18n.js` (currently
`"en"`; set it to `"nl"` or `"de"` to change it).

> The line-up on the tour page is an **invite wishlist**, not a booking. Nobody
> listed has been contacted, and the page says so in three languages.

## Beta guardrails

- `noindex,nofollow` on every page + the yellow BETA banner come from
  `build.py` (the `beta-flag` div and the robots meta) — remove both there
  when testing is done.
- The cart persists in the browser via `localStorage` (with an in-memory
  fallback where storage is blocked). Checkout, account and newsletter forms
  are stubs — nothing submits anywhere.
